# ロードマップ（2026-11-11 作成）

## プロジェクトの目的（2026-11-11 確定）

> **調べて選ぶ人を増やし、公約を検証できる記録を残す。**

- 「投票率を上げる」は長期の理想として持つが、このサイト単体での効果は小さい（研究上、比較サイトの効果が確かなのは「候補者の立場への理解」であり、投票率への効果は小さいか不確か）。成果は次の指標で測る。
  1. 利用者数、ページ末尾アンケートで「投票先を考えるのに役立った」と答えた割合
  2. 公報の内容が、同じ形式で選挙ごとに記録として残っていること
- サイトは「比べる材料を出すところまで」。**おすすめ・順位・マッチング結果は出さない**（StemWijzer の最大の弱点は、設問選び・計算方法で結果が変わること。個人運営で順位を出すと特定候補を有利にしたと受け取られうる）。

- 【CC】Claude Code が実装・作業する
- 【人】こばやしさんが判断・作業する（Claude Code は準備や下書きまで）

## P3：次回以降（2027年春の千葉県議選、2030年の市議選）

StemWijzer・smartvote・VOTE411 に学ぶ「共通アンケート方式」。**準備は選挙の半年前から**始める（StemWijzer は設問づくりと回答確認に数か月かけている）。

- [ ] 【人】一緒に運営する仲間を集め、任意団体として名前を付ける（回答率と信頼性のため）
### 共通アンケート「3問×200字」（柱となる施策）

ドイツの公共放送WDRの Kandidatencheck（全候補に同じ3問、1回答最大1分、無編集で掲載。地方選挙で約1,200人が参加）の文章版。質問を3つに絞ることで候補者の負担を減らし、回答率を上げる。動画版は撮影・保管・字幕の手間が大きいので採らない。

- [ ] 【人＋CC】**質問を決める（告示の4〜6か月前）**：オンラインのフォームで市民に「市議会で議論してほしいこと」を募り、多かったテーマから3問を作る（ProDemos の市民パネル、スイス・ケーニッツ市の市民による設問づくりが手本）。うち1問は「立候補した理由」など全員が答えやすい共通の質問にする。賛否型の設問を入れる場合は「賛成／反対／どちらとも言えない＋理由」の形にし、賛否が分かれない設問は除外する
- [ ] 【人】**送る（告示の2か月前ごろ）**：立候補予定者を報道・本人の発信で把握し、選管にも予定者情報の提供が可能か確認する。依頼は郵送とメールの両方で、**全員に同じ日・同じ締切**で送る
- [ ] 【CC】**回答を集める**：Googleフォームで各回答を200字以内に制限する。なりすまし防止のため、候補者ごとの個別確認コードを依頼状に記載し、フォームに入力してもらう
- [ ] 【CC】**公開前に本人確認**：掲載予定の内容を各候補者に送り、誤記がないか確認してもらう
- [ ] 【CC】**掲載（告示日以降）**：原文のまま掲載し、無回答は空欄で示す（VOTE411 方式）。「64人中〇人が回答」の**回答率を表示**する（ドイツ abgeordnetenwatch.de の回答率表示が手本。答えることが候補者の評判になる）
- [ ] 【人】**公開時期は選管に確認**する。告示前の公開は事前運動と受け取られるおそれがあるため、原則は告示日以降

## 見送る施策（個人運営では難しい）

- **市民から候補者への公開質問機能**（abgeordnetenwatch.de 型）：誹謗中傷や選挙違反にあたる投稿を毎日確認する体制が必要。複数人の団体になるまで見送る
- **公約の実現度の採点**（Polimeter 型）：研究チーム規模の作業量が必要で、中立性のリスクも大きい。代わりに P2 の「議会活動へのリンク」で事実だけを示す
- **候補者の動画掲載**（WDR 動画版）：撮影・保管・字幕の負担が大きい

## 変えない方針（全期間）

- 情報源は公報（次回以降は候補者本人の回答）のみ。外部情報で補わない
- おすすめ・順位・マッチング結果は出さない
- 人が原文と照合したものだけを公開する
- 全候補者を同じ手順・同じ形式で扱う
- 印刷して配る、電子メールで一斉案内する手順や機能は作らない
